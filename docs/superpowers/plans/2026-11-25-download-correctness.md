# 下载正确性修复方案（v1.0.5）

**日期**: 2026-11-25
**状态**: 已实现，已通过自动化测试，尚未真机验证

## 目标

让「下载完成」可信：下载不再静默丢内容，结果页如实汇报本次拿到了什么、漏了什么。

对应代码审查里的 5 条静默丢数据路径：

1. 断点续传跳过没处理完的微博
2. 长文 / 图片获取失败被吞掉
3. 「我的收藏」带着看不见的时间范围
4. 较早的自定义时间段被截断
5. 抓取阶段没有断点

## 不做

- 增量更新（只补新微博）、关闭窗口确认、日志框架、Windows/Linux 应用内更新、403 处理、发布流程、死代码清理——留到下一批。
- 断点续传仍不补抓「中断之后新发布的微博」，那属于增量更新。

## 方案

### 1. 抓一页、处理一页、存一页

原来先把整个账号抓完，再逐条取长文。断点里的 `last_page` 是「抓到第几页」，所以在长文阶段停止后，续传从最后一页之后开始，没处理的全部丢失。

改成每抓一页就立刻处理并追加到已保存列表，`last_page` 的含义变成「这一页及之前的都已处理并保存」：

- 续传从 `last_page + 1` 开始，不会漏，也不会重复。
- 抓取阶段也有了断点（原来没有）。
- 不再把整个账号的原始数据攒在内存里。
- 断点带 `schema: 2`；旧版本写的不续传，因为它们的 `last_page` 含义不同。
- 断点匹配条件补上 `min_text_length` 和 `ignore_deleted`：改了筛选条件就从头下载。

### 2. 进度显示

全程一个进度：`FetchingPostList` 事件带 `current / total`，前端据此算百分比。指定时间段时 API 的总数没有意义，`total` 记 0，前端显示页数和条数。重试事件不再把「第几次重试」写进 `current / total`。

### 3. 失败处理

- `Cancelled` / `InvalidCookie` / `NotLoggedIn`：停止整个任务，返回前保存断点。
- 长文的其他错误：保留截断内容，计数，最后汇报。
- 图片下载失败：计数，最后汇报（导出时回退到原始链接）。
- 删除「连续 50 页不在时间范围就停止」的上限，改由「整页都早于开始日期」自然结束。
- 新增保护：连续 3 页只返回已保存过的内容，提前结束并说明原因。

### 4. 结果汇报

`start_download` 返回 `DownloadOutcome`：`saved`、`longTextFailed`、`imageFailed`、`resumedFromPage`、`stoppedEarly`。结果页在有任一非零或非空项时显示提醒。

### 5. 其他

- 「我的收藏」的请求不再携带时间范围（界面上本来就没有这个控件）。
- 停止后提示「进度已保存」，并提供「继续下载」。
- 后端加运行锁：同一时间只允许一个下载任务。

## 可测试性

- `services/source.rs`：`WeiboSource`（取用户信息、取一页、取长文）和 `ProgressSink`（进度事件）两个 trait。
- `services/pipeline.rs`：`DownloadService::run_with` 只依赖这两个 trait 和 `AppState`，可以用假数据源测试；`run` 负责接上真实客户端和窗口。
- `downloader.rs` 只保留纯函数（日期解析、字数统计、文件名等）。

## 独立审阅后的补充修复

独立审阅的结论是「修复后可合并」，没有 Critical 问题。以下问题已处理：

- 「我的收藏」从第 1 页起显示 100%：微博不对收藏报总数，现在没有总数就不显示百分比。
- 导出一次后结果页的缺漏提醒消失：回到导出页、做完画像分析都保留上一次的下载结果。
- 断点写盘失败时仍提示「进度已保存」：改为只在磁盘上确实有断点时才提示，页码和条数取自真正写盘的那一份。
- 正文里出现「展开/全文」的普通微博被算成长文失败：接口现在区分「请求失败」和「这条微博没有长文」，后者只在微博自己标了长文时才计为缺漏。
- 暂停期间博主删过微博，续传会漏掉相邻一条：续传改为从最后一个已处理页重新读起，并把博主主页的微博按发布时间排回原序。
- 重试事件让进度条闪回转圈：重试改用独立的 `Retrying` 阶段，只记日志、不动进度条。
- 登录失效的错误页不提进度已保存：现在会说明重新登录后再点「开始下载」即可接着下载。
- 换账号后收藏的断点会串：收藏请求带上当前账号的 uid，断点不再跨账号复用。
- 测试补齐：页内中断后续传、收藏模式、图片阶段停止后续传、暂停期间上游删除与新增、App 层「继续下载」。

仍然没有做的（审阅者列出、属于既有行为或下一批范围）：

- 连续两个空页即视为时间线结束并报告完成。
- 「我的收藏」按收藏时间排序，所以续传重叠页里捞到的微博可能排在末尾。
- `state.rs` 里几个不再写入的计数字段，以及 `to_weibo_post` 对 `tauri::Wry` 的依赖，留到清理批次。
