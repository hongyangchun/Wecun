# 第 4 步：增量更新、画像分析、403 与全局限速

**日期**: 2026-11-25
**状态**: 已实现，已通过自动化测试；未真机验证

## 403 与全局限速

- 判断登录是否失效只看响应正文（跳转到 `retcode=6102`、带 `wbBotDetector` 的空壳页），或者 401。403 和 418 不再触发登出。
- 403、418 和 429 先按限流重试（间隔 2、4、8 秒）；仍被拒绝就停止下载，保留断点和登录状态，提示里写明「登录状态没有改变」。长文请求被拒绝时同样停止，不留下截断的微博。
- 所有发往微博的请求共用 `AppState` 里的一个节拍（每秒一次），并发的调用者各占一个时刻。取当前账号 uid 的两处请求也纳入。
- 依据：仓库测试里保存的两种「确实已登出」的真实响应，状态码都是 200，靠正文识别。手头没有 403 的真实样本，所以 403 的归类是从「微博会用 403 限流」这一已知行为推出来的。

## 增量更新

每次开始下载时，按保存目录里已有的内容三选一：

| 目录里有什么 | 这次做什么 |
|---|---|
| 没有缓存，或别人的备份 | 完整下载（和以前一样） |
| 同一套设置的断点 | 从断点续传 |
| 同一位博主、同一套规则的已完成备份 | 更新：从第 1 页抓到第一页的微博全都是这份备份处理过的为止 |

- 「处理过」指保存了，或者按规则跳过了（转发、太短、已删除）。跳过的微博编号随备份一起保存，所以带筛选条件的备份更新时也只读一两页，不会把整个时间线再走一遍。
- 是否停止只看这份备份当初处理过什么，不看本次运行处理了什么。博主新发了一整页转发时，更新会继续往下找原创，不会误以为到底了。
- 只有证据完整才记为跳过。长微博因为没取到全文而显得太短，不算跳过，下次更新会再试一次。
- 新微博排在原有数据前面；博主主页的备份再按发布时间排一次。
- 两种情况不更新而是完整下载，并在结果里说明原因：内容规则变了（原创/全部、字数、忽略已删除），或时间范围往前扩了。时间范围收窄或只改结束日期仍然更新。
- 勾选「重新完整下载」会先清掉缓存，再完整下载。
- 更新被中断后，断点里记着更新的起点和这份备份当初跳过的微博，再点开始仍按更新续传：从第 1 页重新检查。已经读过的页不会重复处理，中断期间新发的微博也能补上。

数据上的改动：

- 已完成的备份多了一份描述 `backup.json`（作者、条数、规则），`posts.json` 里也记一份。写断点时撤掉描述文件，所以被中断的下载不会被当成已完成的备份。
- `DownloadRequest` 多了 `fresh`；`DownloadOutcome` 多了 `added`、`unchanged`、`startedOver`。

界面上的改动：选好目录和目标后，工作台显示「此目录已有 @某博主 的备份，共 N 条」，提供「导出已有备份」；高级选项里多一个「重新完整下载」。结果页把「更新完成（新增 N 条，原有 M 条未改动）」和「下载完成」分开。

界面只在前端的规则和时间范围与备份记录的一致时才说「只会补上新微博」，否则提示会完整下载并替换这份备份；勾了「重新完整下载」时提示已勾选。这个判断在 `src/lib/validation.ts` 的 `canUpdateBackup`，和后端的 `update_allowed` 是同一条规则的两份实现，改一处要同时改另一处。「重新完整下载」只对它开启的那一次下载生效，下载开始时自动取消。中途停止后再点「继续下载」是续传，不会从头再来。

已知限制：

- 更新只补新发的微博。博主后来删除或修改的微博不处理，已删的会留在备份里。
- v1.0.6 及之前做的备份没有描述文件，会先完整下载一次，之后才能更新。
- 目录里 A 的备份被一次中断的更新占用后，如果改了设置再下载，这次会完整下载并覆盖缓存。已导出的文件不受影响。
- 上次没有抓完的备份（例如当时被微博限流而提前结束），更新到第一页就会停，补不齐当时没抓到的部分。这种情况需要用「重新完整下载」。
- 备份收藏时记录的是当前登录的账号。如果启动时没取到当前账号，会按空账号记录，两份这样的收藏备份会被当成同一份。

## 画像分析

- 面板展示本地统计：总数与原创占比、发帖频率、最活跃日期、正文字数、常发地域、24 小时时段、星期分布、按月趋势。不需要密钥。
- AI 密钥存在应用数据目录的 `ai-key` 文件里，从创建起就仅本人可读；可以在界面里填写、更换、清除，AI 分析成功之后也保留这两个入口。原来的位置在可执行文件旁边，在 .app 包内、Program Files 下和 AppImage 里都写不进去。
- 环境变量 `DEEPSEEK_API_KEY` 只在调试构建里生效。正式版如果认它，会覆盖用户在界面里设置的密钥，而且「清除密钥」清不掉。
- 必须用户主动填写密钥才启用，界面上写明会把最多 200 条微博发送给 DeepSeek。
- AI 调用失败时，面板显示原因。请求时直接要求 JSON 对象。

没有决定的事：AI 分析会推断博主的年龄、性别、政治倾向等属性。这次没有改动这些字段。
